# 怎么写 compose（最佳实践）

作者只说清 **结构、关系、强调**；外观由目录默认样式和 AI 选的 token 决定。不要写颜色、圆角、字重、阴影当作者输入。

## 怎么说清意图

1. **分几块**：三列并排、五层自上而下、还是上下两行。
2. **每块叫什么**：图上要出现的短词；解释放下一行。
3. **谁连谁**：先后、分叉、汇合；没有顺序就写明。
4. **哪块是重点**：直接点名（「中间 Role 是重点」）。

然后对 AI 说「编译这篇」：意图进 `<intent>`，结构变成标签树。

## 改写前后

**只写主题（不够）**

> 画一张权限图

**说清结构（最佳实践）**

> 三列：User 下面 Alice、Bob；Role 下面管理员、审核员；Permission 下面 orders:read、orders:approve。Role 在中间把用户和权限接起来，Role 是重点。

**样式指令（不要）**

> 中间浅灰圆角、字重轻一点、箭头用蓝色

**关系 + 重点（要）**

> 用户浏览器先到身份提供方，再同时连到 HR、Finance、Project。三个系统信任同一个身份提供方。身份提供方是重点。

## AI 侧怎么画

1. 选结构：`row` / `stack` / `grid` / `lanes` / `steps`。
2. 用 token 做表面：`padding` `gap` `background` `radius`，而不是新专用组件。
3. 状态用 `<icon name="…">`，不要用 emoji 或位图。
4. 连接优先原子拼；`arrow`/`fan`/`join`/`lanes` 只是糖。
5. 禁止为单张图发明 `SlidingWindow` / `PushFlow` 之类标签。
