## 什么时候用

适合用来写有明确先后顺序的事情：比如线上故障复盘的分钟级记录、一个协议从第一版到第三版的变化，或者一个请求从发出到返回的几个阶段。

如果只是普通的1、2、3操作步骤，直接写 Markdown 有序列表会更紧凑。

## 效果与写法

```garden timeline
title: 一次连接池打满故障的排查经过
items:
  - date: "14:02:10"
    title: "网关 502 报错触发告警"
    text: "监控显示上游服务的活跃连接数在 15 秒内冲到 4096 上限，新请求全部卡在排队队列里。"
    source: "监控指标 · upstream_cx_active"
  - date: "14:05:40"
    title: "查看机器上的连接状态与线程栈"
    text: "发现 3800 多条连接停在 CLOSE_WAIT 状态，工作线程全卡在同步域名解析的锁上。"
  - date: "14:09:15"
    title: "开启本地异步 DNS 缓存"
    text: "下发配置开启 60 秒本地缓存后，卡住的线程在 1 秒内排空，连接池水位降回 12%。"
  - date: "14:20:00"
    title: "补上单次请求超时限制"
    text: "给所有下游调用统一加上 1.5 秒超时，防止个别慢节点再把上游连接池拖垮。"
```

## 可用字段一览

| 字段名 | 必填 | 说明 |
| :--- | :--- | :--- |
| `title` | 否 | 时间线最上方的总标题。 |
| `items` | 是 | 时间节点列表。 |
| `items[].date` | 否 | 节点左侧的时间、日期或阶段名称（如 `"2026-10"`、`"14:02"`、`"第一阶段"`）。 |
| `items[].title` | 否 | 节点标题。 |
| `items[].text` | 否 | 节点详细说明。 |
| `items[].source` | 否 | 节点下方的小字出处或日志来源。 |
