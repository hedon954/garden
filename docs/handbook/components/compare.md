## 什么时候用

当文章里需要对比两种方案（比如「同步复制 vs 异步复制」、「改之前 vs 改之后」）时，用 `garden compare` 可以把它们左右并排摆在一起。

> [!NOTE]
> 每个对比格里的说明建议控制在 **60 个字以内**（写太长的话 `make check` 会提醒你精简）。并排对比只放核心差异，长篇展开请写在普通段落里。

## 效果与写法

### 写法一：带标题、说明与底部属性对照

除了 `title` 和 `text` 以外，你在每项下面多写的任何字段（比如「数据丢失风险」「延迟表现」），都会自动排成底部对齐的属性表：

```garden compare
items:
  - title: 同步多数派复制
    text: 主节点等至少一个副本写盘成功后再返回成功。
    数据丢失: 零丢失（强一致）
    写入延迟: 取决于跨机房 RTT
    适合场景: 账务与元数据
  - title: 异步批量复制
    text: 主节点写完本地盘立即返回，后台按 4 MB 异步发副本。
    数据丢失: 断电差几毫秒
    写入延迟: 仅受本地盘影响
    适合场景: 日志与监控指标
```

```yaml
# 代码块开头写：```garden compare

    text: 主节点等至少一个副本写盘成功后再返回成功。

### 写法二：一句话简写（「标题：说明」）

如果不需要底部的属性表，可以直接在 `items` 里写一行行文字。冒号前面的词（20 字以内）会自动加粗变成标题：

```garden compare
items:
  - "主动发包探测：定时发心跳包检查，多久能发现故障是固定的，但空闲时也会产生额外流量。"
  - "被动按错误熔断：直接统计真实请求的连续超时次数，平时零额外流量，但没请求时不会触发。"
```

## 可用字段一览

| 字段名 | 必填 | 说明 |
| :--- | :--- | :--- |
| `items` | 是 | 要对比的条目列表（电脑端 2–3 项自动并排，手机端自动上下排列）。 |
| `items[].title` | 否 | 这一栏的小标题。 |
| `items[].text` | 否 | 这一栏的说明文字（不超过 60 字）。 |
| `items[].<任意字段名>` | 否 | 除 `title` 和 `text` 以外写的任意键值对，都会自动显示在卡片底部。 |
