# Garden Compose
Edit only authorized posts/blocks. Advice-only means no writes. Never automatically commit, publish, install dependencies or modify this skill during article work.

## Reader question → constraints → recommended route → source leaves → verification
1. The author supplies prose plus one desired effect/image and optional don'ts. Separate facts, appearance and edit scope. Preserve wording, order, complete paragraphs and resources; invent no summaries, numbers or causal arrows. Keep ordinary Markdown when sufficient.
2. Read references/visual-selection.md before selection. Internally derive the geometry card: reader question, shared containers, hanging/body scope, centering target, typography relative to body, scene/internal/background layers, narrow-screen fallback and don'ts. This is AI working context, not author paperwork or runtime attributes. Use documented defaults for harmless ambiguity; ask only when facts, hidden content or reading order face material tradeoffs.
3. Choose one **recommended** route, not a closed component whitelist: icon-rail; short flow-row or long flow-stack; equal-cards; centered-chip; prose-list. frameless-scene is an orthogonal option, as are tone and size. Demand-load the matching references/layout-recipes.md section; unfamiliar layouts/images require references/rendering-model.md. New combinations use references/composition-patterns.md while retaining the same constraints.
4. Use one garden compose fence. Compare requires real shared comparison dimensions, not unrelated cards. Ordinary icon-led editorial paragraphs default to generic icon-rail; native icon-list is an exception for required semantic/host behavior with its actual styling limitations. Never recommend the removed garden list fence. Read references/static-play.md only for needed semantic/state capabilities; query the actual installed schema for props, children and icons. Markdown/safe HTML islands preserve full blocks; restricted expressions are not arbitrary JS.

## Write and verify
1. Read references/workflow.md; scan and preserve target id/line, whole-fence base hash and source. Initial insertion is not apply. An uncompiled intent is not finished output.
2. Follow centralized references/rendering-model.md pitfalls: icon-rail needs icon plus one shared right group containing heading and every paragraph/list; dividers separate rows. row>stack adds contextual top padding; row title/text flex:1 and center couples axes/text. Static unknown attributes may be ignored. Use group where the recipe requires it; do not assume direction="row" changes a stack.
3. Body defaults inherit actual dynamic article family/size/line height. Do not shrink to fit. Explicit size needs a meaningful hierarchy or explicit author request. Scene frame, internal border and background are separate controls (references/frames.md); colors only as needed. Editorial prose prefers a frameless outer figure; independent experiments may retain a boundary.
4. For micro-edits, modify only necessary candidate attributes/leaves, not component families. Stable id when available, otherwise freshly scanned line; always original complete-fence base and candidate file. Apply still replaces a whole fence: no attribute-patch or dry-run API. On conflicts rescan, never bypass protection or overwrite neighbors. Distinguish source bold markup from title's default weight.
5. Run unchanged scripts/check.mjs plus garden check. Optional scripts/lint-layout.mjs uses a scratch constraint JSON and authoritative installed parser; workflow documents its limited structure coverage and exit codes. Risks are not global syntax errors. It cannot recover ignored attributes or prove fidelity/geometry.
6. Under complete theme/CSS order verify desktop+narrow geometry/computed styles and any actual interaction. centered-chip remains a browser-pending candidate; flow must not leave right arrows in a vertical fallback. Report accepted structure, render, browser geometry/interaction and independent clean-context model reliability separately. Missing evidence means unverified.

Scripts use only the installed local engine, no parser copies, downloads, default model calls or catalog dumps. Report missing dependencies. Shared references are demand-loaded; propose reusable maintenance separately from article editing.
