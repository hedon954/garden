# 配方：计划与清单

**读者卡在哪：** 步骤多、要跟着做，读者一边操作一边回来找"做到哪了"。

**什么时候用：** 部署步骤、排查清单、做菜时间线、迁移步骤。读者真的会照着一项项做。

**什么时候不用：** 只是概念上的几个阶段（写列表）；步骤之间有状态变化要观察（用步进器）。

**作者可能这样说：** "给一张可勾选的清单""照着一步步做""时间线"。

**骨架：** 一个 `Checklist`，每项写清时间或顺序、要做什么、注意什么。前面可以放一个决定清单内容的输入。

````md
```ui
---
id: roast-timeline
caption: 大部分活都在客人到之前做完；开饭前一小时只剩烤土豆和做肉汁。
intent: |
  给一张周日烤羊腿的时间线清单，假设 5 点开饭，让读者一项项勾掉。
---
<Checklist title="周日时间线" items={[
  { time: "前一天", title: "做好苹果酥，腌羊腿", note: "盐、蒜、迷迭香、橄榄油，冷藏过夜" },
  { time: "12:30", title: "羊腿出冰箱回温" },
  { time: "13:30", title: "羊腿进烤箱", note: "用温度计判断熟度，不要只看时间" },
  { time: "14:30", title: "土豆焯水、沥干、摇出毛边" },
  { time: "15:30", title: "羊腿出炉静置，烤土豆和蔬菜" },
  { time: "16:15", title: "做肉汁，烫青菜" },
  { time: "16:45", title: "切肉装盘" },
  { time: "17:00", title: "开饭，苹果酥回炉加热" },
]} />
```
````

**要点：**

- 每一项以动作开头（"腌""切""检查"），不要写成名词。
- 注意事项放进 `note`，不要塞进 `title`。
- 清单里的时间和数量来自原话；原话只给了开饭时间时，可以按常识倒推，但要在回复里说明哪些是推出来的。
- 读者需要先选一个参数（人数、环境）时，前面加一个 `Choice`，`items` 用三元在两套清单间切换。

**常见错误：**

- 超过 30 项（拆成准备、当天两块）。
- 把要观察的过程写成清单。
- 想让勾选状态影响别的组件：`Checklist` 不能绑定。
